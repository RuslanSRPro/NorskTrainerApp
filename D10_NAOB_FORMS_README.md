# D10: формы существительных из NAOB

Согласовано 16.10.2026: «если нет форм в Ordbøkene, то смотреть в NAOB». Ставится **поверх** D10_help_sources_v2 и D10_compound_surface_v2. Всё добавляется: `lexeme_form_display_v2`, его снимки и формы составных слов не меняются.

## Когда берутся формы NAOB

Все условия сразу:

| Условие | Зачем |
|---|---|
| Карточка — **существительное** | Подписи глаголов и прилагательных в NAOB другие. Добавлю их по образцу страниц |
| У карточки **нет** форм Ordbøkene и нет форм по главной части (vinterjakke) | Один источник форм на слово, без смешивания |
| Цепочка форм ответила «статьи Ordbøkene нет» | Сбой Ordbøkene не считается отсутствием статьи |
| В поиске NAOB есть статьи с **тем же заголовком** и частью речи «substantiv» | Статья глагола (brenne_1) не читается |

## Что берётся

- Только то, что NAOB показывает в блоке «BØYNING».
  - brenne: **en** brenne, brennen, brenner.
  - «Bestemt form flertall» NAOB не даёт, поэтому строка не строится (brennene не добавляется).
- Неопределённая форма единственного числа = заголовок статьи. Артикль берётся из строки «ubestemt artikkel».
- Если у статьи есть только род и артикль (как у vinterjakke), форм нет и ничего не пишется.
- Если NAOB отдаёт страницу без готовой разметки, разбирается её копия в скрипте страницы.

## Несколько статей одной части речи

У brenne три статьи-существительных (brenne_2/3/4).

- Все статьи с формами дают **одинаковые** формы → формы публикуются.
- Формы **разные** → пометка «на проверку» (`private.d10_naob_forms_review_v1`), ничего не пишется. Прежние строки NAOB этой карточки удаляются.
- Статьи только с родом не мешают решению.

Страниц brenne_3 и brenne_4 у меня нет. Поэтому результат brenne пока неизвестен: формы или проверка. Ответ покажет проба (шаг 7).

## Где хранится и как показывается

- Новая таблица `lexeme_naob_forms_v1`. Запись только через `d10_publish_naob_forms_v1`. Сервер сам проверяет:
  - карточка — существительное, у неё нет своих форм и форм по главной части;
  - ключи — только четыре формы существительного, без повторов;
  - каждое значение — одно слово;
  - неопределённая форма = лемма;
  - есть хотя бы одна форма кроме леммы;
  - есть номера статей NAOB.
- **Приложение** читает эту таблицу, только если у слова нет ни форм Ordbøkene, ни форм по главной части. К названию формы добавляется «· NAOB»: «best. ent. · NAOB».
- Как и формы с «≈», эти формы попадают в упражнения. Если их там не нужно, скажите: уберу.

## Формы в тексте

В `collect_surface_candidates` добавлен блок C. Например, «brennen» в тексте → brenne (сущ.).

- Приоритет 84/83. Это ниже точного совпадения с леммой (85), поэтому разбор самой леммы «brenne» не меняется.
- Блок C выключается для слова, как только у него появляются формы Ordbøkene или по главной части.
- Блоки A, B и E скопированы без изменений. Миграция останавливается до любых изменений, если текущая функция отличается от версии 142.
- **Влияние:** «brenner» теперь находит и сущ. brenne (мн. ч.), с приоритетом ниже глагола (95). Так же ведут себя формы Ordbøkene у любых омонимов (henger). Первым кандидатом остаётся глагол.

## Где это запускается

В цепочке форм (`job-enrichment-batch-worker`), после шага составных слов, для слов страницы, где Ordbøkene ответил «статьи нет».

- Вызывается новая функция `naob-forms-worker`. Глаголы и прилагательные она пропускает сразу, без запросов.
- Это добавка: её сбой **не меняет** результат форм и не останавливает задачу. Итог виден в `compound_v1.naob_forms` результата цепочки.
- Сбой NAOB → ошибка только для этого слова, ничего не пишется, повтор при следующем аудите.
- Ограничения на один вызов: не больше 4 статей на слово, 8 с на страницу, 40 с на вызов. Остальные слова → `deferred`, повтор при следующем аудите.

## Проверено

- **15 тестов Node** на твоих страницах:
  - поиск brenne: 4 статьи, 1 глагол и 3 существительных;
  - brenne_2: en; brennen, brenner; лишняя форма не строится;
  - vinterjakke: форм нет;
  - разбор копии из скрипта;
  - «eller», скобки, словосочетание как значение;
  - публикация (статья глагола не читается);
  - разные формы → проверка;
  - свои формы или формы по главной части → без запросов;
  - глагол;
  - нет статьи-существительного;
  - неполный список поиска;
  - сбой NAOB 503;
  - отказ сервера;
  - лимит времени.
- **Миграция на PostgreSQL 16.** Применена на функции из 142, повтор ничего не меняет. Проверено:
  - публикация brenne;
  - «brennen» → brenne (сущ.);
  - «brenner»: глагол 95, сущ. 84;
  - лемма «brenne» не изменилась;
  - 8 отказов;
  - появились свои формы → блок C молчит;
  - пометка удаляет строки, новая публикация снимает пометку.
  - Откат 149b вернул функцию точно (md5 как после 142). Повторная установка после отката проходит.
- **Синтаксис** всех файлов, строгая проверка типов файлов форм. Окончания строк исходных файлов сохранены.
