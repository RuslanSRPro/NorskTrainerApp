## Как сейчас выбирается карточка (по живому коду)

1. `collect_surface_candidates` → `merge_surface_candidates` → `resolve_surface_form_v2`: строка-кандидат на каждый `lexeme_id`. «bok» даст обе карточки, «boker» — только bok II, когда у неё будут формы.
2. `analyze-text/surface-resolver-v2.ts` `selectByContext`: на каждую часть речи берёт **первого** кандидата. Порядок: приоритет, лемма, часть речи, `lexeme_id`. При двух карточках одной части речи первой оказывается случайная, по UUID.
3. Проверка Ordbøkene (lexical-worker): привязанные статьи берёт из `lexeme_form_display_v2.article_ids` лексемы элемента.
4. Продвижение (`promote_verification_results_for_job`): ищет и создаёт лексему по (лемма, часть речи).

## Решения 14.10 (пункты 9 и 10)

- **п. 9, переводы Lexin:**
  1. Часть речи записи Lexin должна совпасть с частью речи карточки. Это обязательно.
  2. Если у двух карточек одна часть речи, запись относится к той карточке, чьи формы совпадают со склонением в записи Lexin.
  3. Если в записи Lexin нет форм, перевод для этой карточки не берётся и не угадывается: его делает AI по определению своей статьи Ordbøkene.
- **п. 10:** закрывается п. 9. Вторая карточка всегда получает перевод (Lexin по формам или AI), поэтому итог задачи она не блокирует.

## Уточнения механики (после разбора job-orchestrator и lexical-worker)

- **п. 4:** привязанные статьи для проверки Ordbøkene берутся из снимка форм **и** из таблицы привязок. Новая вторая карточка ещё без форм, но уже с привязкой, сразу проверяется по своей статье.
- **п. 7:** новый шаг в job-orchestrator после продвижения, рядом с семейством 360.
  - Для каждого продвинутого слова (глагол, существительное, прилагательное) берутся статьи-омонимы той же части речи: отклонённые в привязке и найденные Ordbøkene.
  - По каждой загружается статья Ordbøkene: римский номер (`hgno`) и формы.
  - Формы отличаются от карточки → создаётся вторая карточка (R9), и в задачу добавляется элемент со своими проверками. Дальше он идёт обычным путём: проверка, продвижение, все цепочки обогащения.
  - Формы совпадают → вторая карточка не создаётся (R8; сентябрьские привязки не трогаем).
- **Открытый вопрос — основная карточка у слова без привязки** (vende, styr и будущие слова):
  - если у слова уже есть карточка, она основная, а статья определяется по её переводу из Lexin (формы записи Lexin);
  - если это не помогает — статья с меньшим римским номером (I).
  - Нужно ваше «ок» или другое правило.
