# D10 — формы V2 в анализе текста и режим «Чтение»

## Что меняется

1. **Распознавание форм слов (V2).** `analyze-text` больше не вызывает старую
   `resolve_surface_form` (старые таблицы форм пусты с 16.09.2026). Кандидаты
   берутся из `resolve_surface_form_v2`, которая теперь читает
   `lexeme_form_display_v2` (официальные формы из Ordbøkene) и точные леммы.
   Выбор части речи по контексту предложения сохранён тем же, что был в старой
   функции (`analyze-text/surface-resolver-v2.ts`).
   Место для грамматического графа отмечено в коде:
   - `surface-resolver-v2.ts` — шапка: выбор по контексту будет заменён графом;
   - `grammar-parser.ts`, ветка `resolutions.length === 0` — `GRAMMAR GRAPH HOOK`:
     сюда встанут правила графа для слов, которых нет в базе.
2. **Режим «Чтение».** `analyze-text` с `analysis_mode: 'read'` возвращает тот же
   разбор, ничего не записывая. В приложении на экране анализа есть
   переключатель «📖 Чтение / 🧪 Аудит» (по умолчанию — Чтение):
   - Чтение: разбор без записи; выбранные слова сохраняются кнопкой
     «💾 Сохранить выбранные в базу» — они идут в базу обычной обработкой
     (проверка, обогащение, допуск к обучению) как список слов;
   - Аудит: как раньше — весь текст записывается и обрабатывается автоматически.
   После обработки сохранённых слов экран сам перечитывает текст (без записи),
   статусы и карточки обновляются.
   Сохранение отправляет каждое выбранное слово или выражение отдельной
   строкой; `analyze-text` разбирает строки списка независимо, поэтому соседние
   выбранные слова не склеиваются в выражение, которого пользователь не выбирал.
   В режиме «Чтение» в словарную базу ничего не пишется; счётчики прочитанных
   слов пользователя (как и раньше) обновляются.

Известное изменение метаданных: теневая функция
`canonical_surface_candidate_batch_v1` помечает кандидатов только из V2 как
`identity_basis = unknown` (она знает лишь старые имена таблиц). На анализ
текста и задачи это не влияет.

Не меняется: старая функция `resolve_surface_form` остаётся в базе (её просто
больше не вызывают); подписи `collect_surface_candidates`,
`merge_surface_candidates`, `resolve_surface_form_v2` прежние; режим «Аудит»
работает как до патча; старое приложение без `analysis_mode` получает аудит.

## Порядок установки

1. Не запускать анализ текстов на время установки.
2. SQL Editor: `scripts/d10/54_d10_forms_v2_resolver_checks.sql` — сохранить
   результат «до» (ожидается: строки D — только базовые формы, C = legacy_tables).
3. SQL Editor: миграция
   `supabase/migrations/20261011140000_d10_surface_candidates_v2_forms.sql`.
4. SQL Editor: снова 54 — ожидается C = `v2_forms`, D близко к `300 / 300`,
   в E у `gikk`, `huset` есть лемма и форма из `lexeme_form_display_v2`.
5. Деплой: `npx supabase functions deploy analyze-text`.
6. Обновить приложение (Expo).

Откат: вернуть файлы из `*.d10-forms-v2.bak`; в базе — прежнее определение
`collect_surface_candidates` (есть в выгрузке функций от 10.10.2026).

## Тест в приложении

Тестовый текст (формы, выражение, слово с двумя частями речи):

```
Han gikk hjem fordi huset var stort. Barna tok med seg maten. Vi skal møte dem i morgen.
```

1. **Чтение, без записи.** Режим «📖 Чтение» → «✨ AI-анализ».
   - В списке «gikk» относится к «gå», «huset» к «hus», «tok med» — выражение.
   - SQL `55_d10_app_test_jobs.sql`: новой задачи НЕТ.
2. **Сохранение выбранных.** Отметить 2–3 слова «нет в базе» → «💾 Сохранить
   выбранные в базу (N)».
   - Появляется значок ⏳ с процентами.
   - 55: одна новая задача, `word_list = true`, только выбранные слова.
   - Когда значок станет ✅, список перечитывается: сохранённые слова
     меняют статус.
3. **Аудит.** Режим «🧪 Аудит» → «✨ AI-анализ» того же текста.
   - 55: новая задача со всеми словами; в `tokens` видно
     `gikk→gå (verb)`, `huset→hus (noun)`, `møte→møte (verb)`.
4. **Карточки.** Открыть «gå» и «hus» (Lexeme360): переводы, примеры, формы.
