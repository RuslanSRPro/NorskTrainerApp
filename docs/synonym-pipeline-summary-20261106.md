# Синонимы в NorskTrainer: полная сводка (состояние на 06.11.2026)

Документ описывает, как сейчас устроена проверка и показ синонимов, какие решения приняты и почему, какие инструменты есть для ручной работы и что осталось открытым. Он охватывает работу 02.–06.11.2026: коммиты `5e85f3f` (проверка и миграции) и `32c73c5` (приложение), а также всё, что было до них в коммите `4c7abc2`.

---

## 1. Принципы

- **Честно и повторяемо.** Одинаковые данные дают одинаковое решение. Сохранённые ответы модели переиспользуются без нового вызова AI.
- **Только словарные переводы.** Переводы берутся из Lexin. Придуманных или «обходных» переводов нет.
- **Строгое правило.** Чистый синоним — это абсолютная синонимия в одном значении: замена работает в обе стороны, и ничего не добавляется и не теряется (ни сила, ни количество, ни манера, ни стиль). Любой намёк на контекст делает пару контекстной.
- **Без ручной разметки.** Решения принимает модель плюс правила в коде. Человек меняет только правила и тестовые ожидания.
- **Без массовых пересчётов.** Ночной обход всей базы выключен. Пересчёт запускается только вручную, с пробным прогоном и известной ценой.
- **Перенос и откат.** Каждое изменение базы — миграция с проверками md5, защитой от повторной установки и откатом в `optional/`.

## 2. Классы пар и что показывается

| Класс (`decision`) | Смысл | Публикуется | В приложении |
|---|---|---|---|
| `verified_synonym` | чистый синоним: замена в обе стороны, ничего не добавлено, та же конструкция, без ограничений | да, если обе проверки перевода совпали | всегда, первым |
| `contextual_synonym` | замена в обе стороны, но есть оттенок, стиль, ограничение или другая конструкция | да, если обе проверки перевода совпали | только при включённой настройке, с пометкой |
| `one_way_synonym` | замена работает только в одну сторону | нет | — |
| `near_synonym` | близкое слово, замены нет | нет | — |
| `rejected` / `related` | не синоним | нет | — |
| `needs_manual_review` | ответы противоречат друг другу или сработала защита | нет | — |

**Класс связи между двумя карточками** (`d10_synonym_publish_link_v1`): связь чистая, только если **все** опубликованные пары между ними чистые (`bool_and`), иначе она контекстная.

## 3. Конвейер проверки

```
кандидат (словарь / соседние статьи)
  -> prepare_candidate (снимок значения, контекст значения; для 'sib:%' — из своей статьи)
  -> очередь пар (synonym_pair_v1, status queued)
  -> аренда пар (d10_synonym_lease_pairs_v1): контракт, модель, thinking, правила, прежний ответ для повтора
  -> проверка связи (edge synonym-verifier, runPairsV12): модель отвечает по подсказке v11b
  -> правила rules_v12 (ruleClassV12) -> класс
  -> запись решения (d10_synonym_record_decision_v1) + запрос проверок перевода
  -> проверка перевода (sense_fit_v2b, все переводы Lexin для значения): совпал ли перевод карточки
  -> триггер публикации (synonym_publishable_v1) -> связь (publish_link) -> карусель v4
  -> пометка контекстного синонима (nuance_v1) -> чип в приложении
```

## 4. Правила r12 (`ruleClassV12`, SQL-копия — `private.synonym_rule_class_v1`)

Из ответа модели (`v11_answer`): обе стороны замены, `same_construction`, `additional_restriction`, `added_component`, `meaning_difference`, а также результат защит (`guard`, `model_class`, `matched_definition`).

1. Сработала защита, кроме `ai_category_contradiction`, `code_category` и `meaning_difference` → класс модели.
2. Нет подходящего значения или ответ «отклонено» → `rejected`.
3. Замена не работает ни в одну сторону → `near_synonym` или `rejected`.
4. Замена работает только в одну сторону → `one_way_synonym`.
5. Обе стороны работают, но есть что-то добавленное, ограничение, разница в смысле или другая конструкция → `contextual_synonym`.
6. Иначе → `verified_synonym`.

Для публикации чистой пары дополнительно нужны `same_construction = true` и `additional_restriction = false`. Для любой публикуемой пары нужно совпадение обеих проверок перевода.

## 5. Пометки контекстных синонимов (nuance_v1)

- **Тест противопоставления (Cruse):** модель составляет фразу «X, но не Y» про одну ситуацию в обе стороны.
  - Обе фразы противоречат сами себе → **`style`**, «тот же смысл, другой стиль».
  - Хотя бы одна может быть правдой → **`meaning`**, «близкий по смыслу».
- Для каждого слова отмечается стиль: `neutral`, `colloquial`, `formal`, `literary_or_archaic`, `regional`, `technical`.
- **Класс пары тест не меняет.** Пометку получают только опубликованные контекстные пары.
- **Хранение:** `private.synonym_nuance_v1` — одна строка на пару и содержание. Если содержание меняется, пару спрашивают заново, а старая пометка уходит в `history`.
- **Функции:** `d10_synonym_nuance_lease_v1` и `d10_synonym_nuance_record_v1` (только для сервиса).
- **Карусель v4** (`get_synonym_carousel_v4`) = v3 + `nuance_kind` + `nuance_style`. В `nuance_style` стиль показанного слова, только если он отличается от открытого. Права такие же, как у v3: без `anon`.
- **Подписи в приложении:** «Близьке значення · розмовне», «Той самий зміст, інший стиль · книжне, застаріле». Английский и норвежский варианты тоже есть.
- **Стабильность:** в тесте на двух прогонах пометка менялась только у одной пары, и та была чистой.

**Состояние на 05.11:** 60 контекстных пар, 55 `meaning`, 5 `style`. После перепроверки 06.11 пометки получили и новые пары, ничего не ждёт.

## 9. Эксперименты и выводы

### 9.1 r13: «разговорное — ещё чистое» + второй ответ (05.11)
- Подсказка v11c добавляет `register_kind`. По правилу r13 пара с разницей только в разговорности остаётся чистой; книжный, официальный, диалектный и технический стиль дают контекстную пару. Если первый ответ чистый, задаётся второй вопрос.
- **Результат 4 прогонов:** U01 snakke → prate был чистым в 2 из 4. E2 (в старом ожидании) ошибался в 3 из 4. Общий счёт не лучше r12. Второй ответ, заданный тем же вопросом, повторяет постоянную ошибку модели и лишь иногда ловит случайную.
- **Решение:** оставить r12. Пакет r13 установлен и выключен (`verifier_rules = 'r12'`).

### 9.2 Почему prate — контекстный (лингвистика)
- По шкале Круза (Cruse, *Lexical Semantics*) слова бывают абсолютными синонимами (замена ничего не меняет ни в одном контексте; это редкость), когнитивными (тот же предметный смысл, разница в стиле или экспрессии) и близкими (можно противопоставить: «killed, but not murdered»).
- Эдмондс и Хёрст выделяют различия смысловые, стилистические и экспрессивные.
- Наш «чистый» соответствует абсолютному синониму в одном значении. prate («говорить легко, непринуждённо») добавляет оттенок, поэтому честно получает класс контекстного синонима с пометкой «близкий по смыслу · разговорное».

### 9.3 skravle: два значения snakke
- **U02:** snakke «говорить» → skravle добавляет «много» → контекстный.
- **E2:** snakke в значении, которое словарь сам определяет как «skravle» → чистый. Рабочее решение snakke → skravle (чистый) верно, ожидание теста исправлено 06.11.

### 9.4 Тест противопоставления стабильнее основной проверки
- На тестовых парах пометка держалась между прогонами, а граница «чистый / контекстный» в основной проверке скакала.
- Пример: H12 enkel → grei сейчас чистый, но тест оба раза нашёл разницу.
- Идея на будущее: делать пару чистой, только если и основная проверка, и тест говорят «смысл один».

## 12. Открытые вопросы и идеи

1. **Спорные чистые пары:** dag → dato, gammel → tradisjonell, tid → øyeblikk. Модель обосновывает их узким значением словаря. Можно прогнать через тест противопоставления.
2. **Тест противопоставления как второе условие для «чистого»** (см. 9.4). Сделает класс строже и стабильнее.
3. **Строки-ярлыки словаря** («brukt som adverb:») в `group_definitions` источника. Можно отфильтровать из контекста значения.
4. **r13 в будущем** — только с подсказкой v11c, которая сохраняет `register_kind`. Пересчёт старых ответов v11b для r13 невозможен.
5. **TypeScript:** `npx tsc --noEmit` захватывает Deno-файлы (`grammar-evidence/tools`, `supabase/functions/_shared/nlp`, `adjective-degree-sql-shadow-v1`), 65 ошибок вида TS5097 и `Deno`. ## 13. Правила работы (для продолжения)

- Пакеты — zip с `install.ps1`:
  - ASCII, CRLF;
  - проверки SHA256: несовпадение → STOP;
  - копии `.bak`;
  - README на русском.
- **Исправленный пакет или запрос всегда получает новый номер и имя.**
- Миграции: проверки md5 без `\r`, повторная установка → STOP, откат в `optional/`, проверка на локальной реплике до сдачи.
- Запросы только для чтения нумеруются (NNN), помечены «ТОЛЬКО ЧТЕНИЕ», вывод в виде `part | name | info`.
- Для уже сохранённых запросов даётся команда копирования из «Загрузок».
- Ключи никогда не попадают в чат и не выводятся скриптами.
- Ничего не удаляется без согласования. Коммиты делает Ruslan по командам и скриптам.
- Обход всей базы выключен, массового пересчёта нет. Ручные режимы — с пробным прогоном.
