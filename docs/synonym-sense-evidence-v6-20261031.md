# Верификация по значению, v6

Причина исправления: source.definition_nb относилось к конкретному словарному значению,
а translations/examples_nb — к карточке целиком. У rask значение «здоровый» проверялось
вместе с переводом fast и примерами скорости; у vanskelig значение характера — с примерами обстоятельств.

В pairInput общие переводы и примеры обеих карточек исключены из запроса AI.
Исходный snapshot сохраняется для аудита и отслеживания изменений. Карточки не изменяются.
Решение строится по конкретному определению источника и выбранному определению цели.
Отсутствие определения цели теперь всегда ведёт к needs_manual_review, даже если AI ответил положительно.
Недостаток перевода конкретного значения не восполняется выдуманным переводом.

Версии Edge Function: 13; prompt/verification contract: v6.
Все остальные файлы развёрнутого обработчика сохранены из production v12.
Новая версия контракта не позволяет использовать старый кеш решения при подготовке пары заново.
Существующая база массово не переобрабатывалась.

Проверка: 20 Node-тестов прошли. Регрессионные проверки доказывают, что подмена общего
перевода/примера не изменяет вход AI; пустые определения не могут дать подтверждение.
Точечно повторно обработаны три кандидата (четыре пары с учётом омонима):
- vanskelig → umedgjørlig: rejected → verified_synonym, значение характера.
- rask → frisk (прилагательное): rejected → verified_synonym, здоровье.
- rask → sunn: near_synonym → verified_synonym, здоровье.
- frisk с несовместимой частью речи: rejected_rule, сохранено.

Это результаты системы, не доказательство общей точности модели. Привязанные к значению
примеры/переводы в будущем можно добавлять только с явной ссылкой на это значение.
