# Синонимы: актуальность, история и фоновые проверки — 31 октября 2026

Изменения применены в Production `kevpkawrbtovrgyjkkvu`.
Функция `synonym-verifier` развёрнута как версия 12, prompt v5.
Массовый обход базы выключен. Сбор и проверка материалов анализа включены.
Канонические переводы карточек этим патчем не заменяются.

## Что изменилось

1. Отложенное семейство 360 сохраняется до подтверждённого полного прогона:
   - завершившаяся инъекция семейства записывает отдельное подтверждение;
   - обычная задача должна быть `completed`, без пропуска инъекции и незавершённых цепочек;
   - наличие карточки в повторной задаче само по себе не снимает отметку;
   - успешный этап без найденного семейства считается обработанным.
2. Синонимы учитываются отдельно от семейства 360:
   - `waiting`: работа ожидает источника, карточки или решения;
   - `deferred`: следующее поколение кандидатов намеренно не создаётся автоматически;
   - `error`: источник недоступен, попытки исчерпаны, нужна ручная проверка;
   - `no_candidates`: текущий извлекатель не нашёл кандидатов в проверенном источнике;
   - `no_verified_synonyms`: среди обработанных кандидатов нет строгих синонимов;
   - `verified`: есть подтверждённые пары, незавершённых кандидатов нет;
   - `not_checked`: нет нового подтверждённого отчёта о сборе.
   Пустой результат успешной проверки не является ошибкой.
3. После анализа пересматриваются связи, где карточка находится с любой стороны.
   Очередь сохраняет весь список; синхронно обрабатываются 50 кандидатов,
   далее крон продолжает. Ограничение 500 больше не теряет остаток.
4. Отпечаток входа и ключ кеша учитывают смысл, переводы, POS, контекст,
   передаваемые примеры, версии pipeline/верификатора. ID запуска не влияет
   на смысловой отпечаток. Повторный запуск с теми же данными не сбрасывает решение.
5. Существующие кандидаты обновляются при повторном сборе.
   Исчезнувшие из успешно обработанного источника кандидаты помечаются неактивными.
   Их карточки сохраняются, старые публикации отзываются. Ошибка источника не
   считается доказательством исчезновения кандидата.
6. Зависимые пары между кандидатами группы тоже инвалидируются при устаревании
   родительского решения. Повторное подтверждение позволяет восстановить такую пару.
7. Крон каждые 5 минут обслуживает готовую очередь, недостающие статьи и
   ограниченные повторы ошибок. Он не перебирает все исходные слова, пока
   `synonym_bm_config_v1.enabled=false`.
8. Восстановление статьи ограничено четырьмя попытками, ошибки подготовки/повтора
   задачи — отдельными конечными лимитами. Исчерпание становится видимой ошибкой.
9. Дневной учёт массового сбора вынесен в неизменяемый журнал.
   Попытка проверки AI резервирует единицу бюджета при выдаче пары:
   потеря ответа/журнала не возвращает израсходованный лимит.
   Лимит проверки пар остаётся 400/24 часа. Это лимит пар, а не общий денежный
   лимит всего приложения: перевод смысловых подписей и обогащение — отдельные операции.
10. Обнаружена и исправлена ошибка NULL в списке словоформ:
    `NOT (candidate = ANY(forms))` мог исключать все кандидаты при NULL.
    Теперь NULL удаляется и в извлечении форм, и в фильтре терминов.
    Маркеры словарных ссылок `jf.` / `se` сохраняются, а не превращаются
    в самостоятельные доказательства синонимичности.

## История всех исходов

- `private.synonym_collection_events_v1`: каждый завершённый вызов учёта сбора,
  в том числе отсутствие кандидатов, ожидание и ошибка; дата, источник, версия
  извлекателя, описание исхода, сведения о статье и её отпечаток.
- `private.synonym_collection_state_v1`: последнее состояние сбора по сущности.
- `private.synonym_pair_events_v1`: полный вход, прежнее/новое состояние,
  положительные и отрицательные решения, правила, инвалидирование, даты.
- `public.synonym_verifier_log_v1`: ответы AI с полным снимком входа и его ключом,
  причиной, направленностью замены, версиями и датой.
- `private.synonym_human_reviews_v1`: оценки проверяющего отдельно от ответа AI.
  `d10_synonym_review_metrics_v1()` сравнивает их только с актуальным снимком.
- `private.synonym_ai_budget_v1`: попытки AI, зарезервированные до запроса.

Новая подробная история начинается с установки патча. Старые отсутствующие
снимки не восстанавливаются искусственно. Повторный аудит создаст актуальную запись.

## Проверка отдельной карточки

См. `scripts/d10/213_synonym_lifecycle_inspect.sql`: обычные запросы только читают.
`d10_synonym_recheck_entity_v1(type,id,true)` принудительно ставит связи выбранной
карточки на перепроверку с обходом кеша и положительного правила.
Команда доступна администратору/service role, не открытому клиенту приложения.
Это проверка существующих кандидатов; для нового поиска и обновления источников
использовать обычный полный аудит слова/выражения.
Массовый `d10_synonym_reverify_v2()` для этого не нужен.

- samtale: contextual_synonym;

Все эти решения имеют историю и дату; исходные карточки сохраняются.

## Границы покрытия

Обработка очереди не доказывает, что найдены все синонимы языка.
Текущий извлекатель ограничен словарными структурами и короткими перечислениями;
многословные кандидаты Bokmålsordboka требуют существующего каталога выражений.
Парсер ограничивает число извлечённых толкований, AI получает ограниченное число
толкований и примеров. Старые карточки массово не перезапускались.

Следующий шаг оценки качества — вручную разметить независимую выборку:
обычные слова, выражения, несколько смыслов, отрицательные пары, односторонние замены.
Для полноты извлечения выборка должна включать ожидаемые пары, которых вообще
нет в очереди. Ответы AI нельзя использовать как единственный эталон для правил.
Сначала правило работает в сравнительном режиме; после оценки ложноположительных
решений на независимой выборке можно разрешать автоматическое подтверждение.
