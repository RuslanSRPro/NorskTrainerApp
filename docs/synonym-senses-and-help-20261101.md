# Значения синонимов и справка

## Согласованный интерфейс
- Мастер-переводы карточки не изменяются. Набор синонимов не ограничивается тремя переводами.
- Заголовок групп: «Значення слова «ta»» (локализован также для en/no).
- Каждая карточка синонима сначала показывает значение исходного слова в связи, затем сам синоним
  и перевод синонима в этом значении. При отсутствии перевода значения показывается норвежское определение.
- Выбор группы продолжает фильтровать карусель. Одинаковые переводы не используются для удаления карточек.
- Лампочка: дополнительные СОХРАНЁННЫЕ переводы значений с норвежскими пояснениями и дата
  последнего запуска анализа из lexeme_processing_jobs.created_at. Не дата изменения lexemes.
  Отдельно отмечен фоновый анализ; при отсутствии записи дата не выдумывается.
- Help RPC принимает ID карточки или связанного выражения. При открытии справки данные перечитываются;
  старый кеш толкований на всю сессию удалён. Необходимости менять мастер-перевод нет.

## Что действительно произошло с ta / stjele
Карточек глаголов по одной. Две проверки: ta→stjele и обратная stjele→ta из дочернего анализа.
Первоначальное правило увидело в статье stjele слово «ta» и подтвердило обратную связь, игнорируя номер значения.
Однако у stjele «ta noe som tilhører en annen» и «legge beslag på; ta» — разные значения (красть / занимать время).
Примеры второго значения содержали подстановку `$` с type_=usage, которая ранее пропускалась.
Теперь подстановки восстанавливаются, примеры передаются только из конкретного раздела словаря.

## Модель отношений и верификация
- private.synonym_sense_links_v1 — каноническая связь концов entity+article+dictionary sense,
  с отдельным массивом evidence_pair_ids. Противоположные проверки — свидетельства, а не новые карточки.
- Идентичность значения опирается на номер раздела статьи; если его установить нельзя — на исходный текст.
  Разные части речи, ID карточек и разные разделы не объединяются по совпадению украинского перевода.
- RPC карусели читает итоговые связи и исключает excluded-карточки. Клиентской маскировки повторов нет.
- Верификатор v8, Edge v18: контекст конкретного исходного значения, определения цели до 80
  (для ta получено 48, ранее в запрос AI попадало 8), строгая проверка конструкции и регистра.
  Сбор кандидатов и число создаваемых дочерних задач не расширялись.
- Простой mutual-reference больше не подтверждает автоматически многозначную цель/сложную группу.
- Подписи значений sense_label_v4 получают тот же словарный контекст: ta/kreve → «брати плату · charge»,
  stjele/ta (время/тепло) → «забирати · take up». Основные переводы остаются прежними.

## Проверка смысла
https://ordbokene.no/bm/ta — fange (2), kreve/stjele (3), straffe (5), время/место (18), движение/транспорт (20).
https://ordbokene.no/bm/stjele — красть (1), занимать/отнимать время/тепло (2).
ta→straffe теперь contextual_synonym; в строгой карусели не показывается.
ta→kreve сопоставляется со взиманием цены, а не с любым требованием.
ta→fange относится к ловле/задержанию. ta→stjele — только к присвоению чужого.
После исправления примеров обратная stjele→ta стала contextual_synonym; вывод модели всё ещё требует
контрольной выборки: объяснение выбора конкретного определения может оставаться неточным.

## Проверка скрытых карточек
У ta/stjele/kreve по одной карточке глагола. У straffe есть отдельное существительное «пенальти».
У fange два существительных с разными статьями/значениями: «заключённый» и «горсть», плюс глагол.
bære II исключена с причиной d10_r9_false_card_no_own_forms_8440; это историческая ложная R9-карточка,
а не механизм удаления всех вторых статей. Исключённые карточки пропускаются повторной инъекцией.
Проверка не дала основания удалять все омографы или сводить разные части речи к одному ID.
