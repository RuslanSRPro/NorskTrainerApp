# 31.10.2026 — только подтверждённые синонимы, сбор по анализу

Кнопки выбора классов удалены. Сервис исключает contextual_synonym и односторонние
связи до построения групп; пустых групп нет. Иконка по входному synonyms видна только
при resolved + verified_synonym. Групповая фильтрация сохранена. Классификатор также
исключает из строгого класса явное отрицательное направление или same_construction=false.
Название «100%» в интерфейс не добавлялось: отображается существующий подтверждённый класс.

Production: synonym_bm_config_v1.enabled=false (массовый сбор),
after_analysis_enabled=true (завершённые задачи анализа). Старые задачи не перезапускались.
Добавлен analysis_job_id у записей обработки BM. Если статьи ещё нет, cron повторяет
попытки только для слов, явно поступивших через этот путь. Необработанные слова всей базы
в этом режиме не выбираются. Обновление переводов, кешей, логов и примеров всей базы не запускалось.

После уточнения пользователя сохранено прежнее поведение дочерних задач:
- корневая задача: origin_depth=0, кандидаты pending;
- дочерняя synonym_candidate: обычное создание/обогащение карточек, сбор собственных
  кандидатов с origin_depth=1 и deferred_depth;
- dispatcher в Production выбирает только pending с origin_depth=0. Поэтому кандидаты
  второго поколения сохраняются, но новые карточки/внучатые задачи автоматически не создаются.
В базе обнаружено 167 записей origin_depth=1 / deferred_depth. Это существующее ограничение,
а не новое отключение сбора. Первоначально добавленный полный пропуск дочерней задачи снят
корректирующей миграцией synonym_child_collection_preserve.

Проверки: 6 тестов интерфейсной политики прошли, eslint изменённых UI-файлов без ошибок.
Общий tsc имеет прежние ошибки других частей проекта, в изменённых UI-файлах ошибок нет.
SQL-тесты с ROLLBACK подтвердили: массовый сбор выключен; завершённая задача собирает свои
слова и сохраняет область повторных попыток; дочерняя задача тоже собирает слова с depth=1.
Финальные настройки повторно прочитаны из Production. Реальный новый анализ текста после
этих изменений не запускался; прежние очереди и результаты не очищались.
