# Синонимы: исправления 30.10.2026

Изменения внесены в локальный проект. В Production применены две миграции
`d10_synonym_display_directions`, `d10_synonym_direction_cache_guard` и развёрнут
`synonym-verifier` версии 11. Приложению требуется обычная перезагрузка с новым кодом.

## Выполнено

1. Направления substitution_forward / substitution_reverse и same_construction сохраняются
   в verification_evidence и журнале. Версия журнала больше не зафиксирована на v3.
   Старые AI-ответы без этих полей не копируются в новые решения. Словарные правила сохранены.
2. Новый RPC get_synonym_carousel_v3 выдаёт отдельные пары значений и направления относительно
   открытой карточки. Старые RPC сохранены для совместимости. Историческое отсутствие направления = null.
3. Значения нумеруются последовательно в окне. Исходный словарный путь сохраняется в данных.
   Статус одного значения больше не распространяется на остальные значения той же карточки.
4. Цвет обозначает класс: зелёный — синоним, синий — контекстный, оранжевый — односторонняя
   замена с явной стрелкой. Это оценка связи в выбранном смысле, не «100%» универсальная замена.
5. Разделены подписи значения исходного слова, значения цели и общего перевода карточки
   (последний находится в подробностях ⓘ). Канонические переводы не менялись.
   Подробности открываются отдельно и прокручиваются. Повторно обработана только противоречивая
   подпись god / stor, romslig. Новый промпт требует одного смысла для обоих языков.
6. Фильтры класса и значения работают совместно. Несколько выбранных классов = объединение;
   ни одного = все допустимые классы. Смена фильтров возвращает карусель к первой карточке.
   Пустой результат не подменяется старой каруселью. Открытие/добавление используют настоящий ID карточки.
   Окно учитывает безопасную область экрана; выбранное значение не меняется при перелистывании.

## Пункт 7: массовый сбор НЕ включён

synonym_bm_config_v1.enabled остаётся false. Причина — проверка качества конкретного примера:
после повторной обработки AI перевёл god (stor, romslig) как «просторий / spacious», а в повторной
проверке пары выбрал для stor значение с подписью «величезний / huge». Механизм сохранения/показа
теперь работает, но языковая корректность этого сопоставления не доказана.

Повторно проверена ровно одна существующая пара god → stor. Старое решение и evidence сохранены
в history с reason=direction_evidence_smoke_20261030. Модель дала forward=false, reverse=true,
same_construction=false; журнал и RPC сохраняют именно эти значения. Это проверка работоспособности,
а не независимое подтверждение лингвистического решения. Остальные исторические пары массово
не перезапускались; оранжевый класс появляется только при сохранённом доказательстве одного направления.

Следующий этап перед включением сбора: проверить выбор значений и направления на примерах
употребления из словаря; сформировать эталонную небольшую выборку. Контекстно-зависимый перевод
подписи не должен считаться достаточным доказательством синонимии.
Настройки лимитов сохранены: 10 новых слов за проход, 100 в сутки, 400 AI-пар в сутки.
Верификатор и существующий supervisor продолжают работать; новый cron не создавался.

## Проверки

- 6 новых тестов: классы/направления, сочетание фильтров, разные смыслы одной карточки,
  сохранение ID и переводов, отсутствие небезопасного fallback, двуязычные подписи, guards.
- 18 существующих тестов верификатора и подписей пройдены.
- SQL-проверка направления с обеих сторон пары выполнена в транзакции с ROLLBACK.
- Production RPC проверен на stor, god, slå ut; один реальный ответ AI сохранён в новый журнал.
- Общий tsc остаётся красным из-за существующих ошибок проекта; в изменённых файлах ошибок нет.
- В общей карусели остаются прежние lint-замечания к эффектам; новые файлы и SynonymsBadge проходят lint.
- Локальный deno check не завершён: DNS не разрешил внешние импорты. Серверная сборка/развёртывание успешны.
- Визуальная проверка на iPhone не выполнена. Нужно проверить длинные выражения и окно подробностей на устройстве.
- Advisor сообщает об authenticated SECURITY DEFINER RPC: это намеренный read-only доступ к общему
  опубликованному словарю, как у v1/v2. Анонимный доступ запрещён; частная история AI не выдаётся.
  Документация: https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable
