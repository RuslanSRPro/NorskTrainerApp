# Правила

Номера используются в `matrix.csv`, файлах этапов и CHANGELOG.

## W — взаимодействие

- **W1** Не придумывать ответы, не обманывать, не скрывать. Не знаю — сказать и проверить.
- **W2** Прежде чем исправлять, убедиться в точности ошибки на данных: запрос, живой текст функции,
  воспроизведение тем же кодом. Не строить правку на догадке.
- **W3** Сначала превью: что будет изменено, почему, что затронет. Делать после согласия.
- **W4** Искать лучшее устойчивое решение, а не заплатку на одно слово.
- **W5** Не удалять и не ломать то, что работает; менять только нужное; перед изменением — резервная копия
  (файлы `*.bak`, строки базы — `private.*_backup_*`).
- **W6** Всегда проверять целостность и отказоустойчивость: кто ещё использует изменённое, что переразвернуть,
  не появится ли нагрузка на базу, что будет при сбое на середине.
- **W7** Найденное по пути — сообщать и обсуждать, не чинить молча.
- **W8** Признавать свои ошибки сразу и прямо.
- **W9** Эффективность: без лишних тяжёлых запросов и фоновых опросов.

## Q — запросы, миграции, скрипты

- **Q1** SQL и PowerShell — готовые к запуску, без ручных правок.
- **Q2** Диагностика — только чтение, лёгкая, с `statement_timeout`.
- **Q3** Изменения — миграцией в `supabase/migrations`, защищённой: точка привязки совпадает ровно один раз,
  иначе ничего не меняется; повторный запуск безопасен; в конце отчёт.
- **Q4** Функцию в базе править по её **живому** тексту (`pg_get_functiondef`), не по старому файлу миграции
  (11.11 точка привязки не нашлась именно из-за этого).
- **Q5** Исправленный / перевыпущенный файл получает новый номер и имя.
- **Q6** Файлы — в «Загрузки». Для сохранённых — команда в буфер:
  `Get-Content -Raw -Encoding UTF8 "$env:USERPROFILE\Downloads\<файл>" | Set-Clipboard`.
  Миграции — тот же вид с путём `C:\Users\subbo\NorskTrainerApp\supabase\migrations\<файл>`.
- **Q7** Развёртывание: `supabase functions deploy <функция>` — для всех функций, использующих изменённый общий файл.
- **Q8** PowerShell: `-ProjectRoot`, UTF-8; сообщения коммита только ASCII (PowerShell 5 читает скрипт без BOM
  в старой кодировке).
- **Q9** Ключи и токены не выводить (скрипты читают `.env.local`). E-mail пользователя — личные данные.
- **Q10** Редактор SQL показывает только последний результат — проверки давать отдельными файлами или `UNION ALL`.

## D — предметные правила анализа

- **D1** Часть речи ИИ не придумывает. Новая карточка части речи — только при зарегистрированной статье словаря
  этой части речи (`registered_entry = true` и `pos_match = 'match'`; Ordbøkene, NAOB, Lexin; Wiktionary пока нет).
  [проверено: `d10_gray_clone_pos_evidence_v1/v2`, 10.11]
- **D2** Серая карточка = низкий уровень проверки (растёт по мере появления источников), а не «вне обучения».
- **D3** Строгие правила сейчас — чтобы накопить чистую базу; проблемное разбирать потом.
- **D4** «Аудит» = полная перезапись результатов слова. [на 11.11 НЕ выполняется полностью — см. HANDOFF]
- **D5** Отдельно отправленное слово (`mode='word_list'`) получает все свои части речи; правило пропуска
  (`analysis_skip_config_v1.skip_since` = 08.11) на списки слов не действует.
- **D6** R8 / R9 (омонимы одной части речи): одинаковые формы → одна карточка, остальные статьи — запись-решение
  без карточки (R8); разные формы → своя карточка с римским номером (R9); разные формы, то же значение
  (вариант / ссылка на главную) → `skipped` + «на проверку». Скрытых подчинённых карточек нет.
  [проверено: `_shared/d10-homograph-cards.ts`, `private.d10_homograph_article_decisions_v1`]
- **D7** Существительное без статьи Ordbøkene делится по статьям NAOB тем же правилом.
  [проверено: `20261024100000_d10_naob_homographs_v1`]
- **D8** Каждая карточка получает контекст только своей статьи своей части речи; переводы соседних карточек-омонимов —
  только чтобы не повторять, не источник смысла. [проверено: `ai-enrichment-worker`, `homograph-translation-guard.ts`]
- **D9** «≈» (низкая надёжность, рекомендована проверка): слово без статьи / статья без толкования / привязка к
  статье NAOB; выражение, подтверждённое словарём целиком, но без толкования; выражение, которое NAOB назвал
  синонимом слова (значение корня). Все «≈» получают перевод + пример + перевод примера; заметки не генерируются.
  Выражения, только упомянутые в тексте без связи, — не «≈», остаются в проблемных. [11.11]
- **D10** ИИ: первая попытка — Gemini генерирует, Gemini проверяет; при отказе — повтор: OpenAI `gpt-6-luna`
  генерирует с причиной отказа и проверяет. Выражения — всегда OpenAI. Защита записи принимает `gemini` и `openai`.
  Если не проходит только пример — перевод записывается отдельным проходом. [11.11]
- **D11** Ссылка «jf. X» (толкование = только ссылка на статью) — `see_also`, никогда не значение. [11.11]
- **D12** Решения о слове, а не сбой задачи (`_shared/d10-review-decisions.ts`): GATE — AMBIGUOUS_POS_WITHOUT_ARTICLE,
  CONFIRMED_*_POS_CONFLICT, NO_CONFIRMED_WHOLE_UNIT_REGISTRATION, unknown_pos_requires_review,
  FAMILY_EXPRESSION_NOT_VERIFIED; ENRICHMENT — AI_POS_SENSE_REVIEW_REJECTED, AI_SINGLE_TRANSLATION_REQUIRED,
  AI_REQUESTED_EXAMPLE_MISSING, AI_SOURCE_PERIOD_CHANGED_TO_NEW_MOON, pos_mismatch_filtered,
  SELECTED_BM_ARTICLE_REQUIRED, SELECTED_ARTICLE_DEFINITION_MISSING, AI_EXAMPLE_HIGHLIGHTS_INVALID,
  AI_EXPRESSION_OWN_DEFINITION_REQUIRED. Всё остальное — сбой (needs_manual_review).
- **D13** Синонимы: только то, что выходит из анализа (дочерние задачи), без мониторинга всей базы;
  показываются чистые синонимы, контекстные — по настройке приложения.
- **D14** Омонимы и семейство NAOB: для карточки из группы омонимов берутся только статьи NAOB, чьи формы
  совпадают с её собственными формами (не с формами соседей). [11.11, развёрнуто, не закоммичено]
