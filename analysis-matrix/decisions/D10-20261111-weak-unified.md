# D10-20261111 — единое обогащение «≈» и синонимы NAOB

**Решение (пользователь, 11.11):** все слабые карточки и выражения («≈») получают одинаковое обогащение:
перевод + пример + перевод примера. Генерирует ИИ, проверяет второй ИИ; при отказе второй ИИ (OpenAI) делает
и проверяет сам. Запись помечается `reliability: low`, «рекомендована проверка». Разница с карточками со статьёй —
только в уровне проверки (звёзды): со статьёй 4–5, «≈» 2–3. Верификация не меняется.

**Граница «слабого» (кого пускать в «≈»):**
- словарь подтвердил слово / выражение целиком, но без толкования — да (было);
- выражение, которое NAOB назвал синонимом конкретного слова (`synonym_candidate_queue`, не rejected) — да, в
  значении корня (ИИ получает корень, часть речи и ряд синонимов NAOB);
- выражение, только упомянутое в тексте без связи и толкования — нет: без опоры ИИ может придумать значение.

**Почему:** карточка без примера неполноценна для ученика; механика примеров для «≈» уже работала в Аудите (27.10);
риск плохого примера закрыт правилом «пример не тянет перевод» (C-1111-03).

**Отвергнуто:** давать «≈»-выражениям только перевод (как было у слов) — неодинаково и беднее для обучения.

**Где:** `ai-enrichment-worker/index.ts` (3 пути «≈»: no-article, definition-missing, NAOB-bound;
`noArticleFieldScope`), `expression-quality.ts` (`naob_synonym_roots`). CHANGELOG C-1111-08.
