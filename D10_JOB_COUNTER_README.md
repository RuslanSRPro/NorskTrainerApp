# D10: счётчик окна задачи (план / факт)

Меняется одна функция: `public.get_job_chain_progress`. Подпись и колонки те же, правила «текущая / завершена» тоже.

| Было | Стало |
|---|---|
| «Сделано» = отметка страницы супервизора. У пакетных цепочек (AI, упорядочивание, канонизация) всегда 0 | «Сделано» = сколько элементов цепочка **завершила** по журналу (готово, нет данных или ошибка) |
| «Всего» = все элементы задачи (14), включая выражения у цепочек слов и все части речи у форм | «Всего» = сколько элементов возьмёт цепочка, по тому же отбору, что и обработчик. После завершения цепочки — сколько она реально взяла. В конце план = факт |

Проверено на живом определении (PostgreSQL 16). До: Lexin 0/4, формы 0/4. После: Lexin 3/3 (повторы одного слова не считаются), формы 2 (только глагол и существительное). По завершении цифры совпадают с журналом. Повтор миграции ничего не меняет.

Это только отображение: `get-job-status` передаёт цифры в приложение, на статус задачи они не влияют.
