# D10 — задача анализа доходит до конца при отдельных сбоях

Цель из плана (§1): один сбой не останавливает остальные элементы. `needs_manual_review` ставится только после того, как вся доступная обработка выполнена, и со списком того, что не удалось.

Обогащение уже работало так после патча остатков (v3). Этот патч закрывает три места, где одна проблема всё ещё останавливала всю задачу.

## Что меняется

1. **Продвижение слов (orchestrator).**
   - **Было:** если продвижение не сдвигалось, задача сразу получала `needs_manual_review`; остальные слова не получали обогащения.
   - **Стало:** до 3 попыток на следующих тиках. Затем закрывается только та страница из 3 слов, на которой продвижение застряло. У этих слов: `status = done`, `current_stage = admission_gate`, `promotion_status = promotion_failed`, плюс статусы их проверок как доказательство. Это тот же вид, в каком продвижение уже закрывает непродвинутые слова. Остальные слова идут дальше.
   - Закрытие выполняется, только если все проверки источников по задаче завершены. Пока проверки идут, ничего не закрывается.
   - Если закрыть страницу не удалось, остаётся прежнее поведение: `needs_manual_review`.
2. **Добавление семейства 360 (orchestrator).**
   - **Было:** ошибка останавливала всю задачу.
   - **Стало:** ошибка передаётся supervisor. После 3 ошибок задача продолжается без новых членов семейства, и это попадает в итоговый отчёт.
3. **Проверка выражений перед обогащением.**
   - **Было:** 3 сбоя страницы останавливали задачу.
   - **Стало:** пропускается только эта страница и попадает в отчёт. На этапе аудита та же проверка выполняется ещё раз, как и раньше.
4. **Сбой целой страницы обогащения** (обработчик упал, страница не загрузилась, 3 таймаута подряд).
   - **Было:** останавливалась вся задача.
   - **Стало:** пропускается только эта страница этой цепочки. Следующие страницы и цепочки продолжаются, страница попадает в отчёт.
   - Ошибки отдельных слов внутри страницы обрабатываются как раньше, через журнал остатков.
5. **Итоговый отчёт.** При `needs_manual_review` в `summary` задачи записываются:
   - `enrichment_failed_items`;
   - `promotion_failed_items`;
   - `enrichment_skipped_pages`;
   - `pre_admission_skipped_pages`;
   - `family_injection_skipped`.
6. **Приложение.** Значок ⏳ идущей задачи больше не пропадает, если запустить другой анализ. Сбрасывается только у завершённой задачи или по кнопке «Очистить».

## Что не меняется

- Журнал остатков, механизмы дробления и повторного прогона страниц, проверка форм, этап аудита, `promote_verification_results_for_job` остаются как были.
- Новые функции только добавляются. Ни одна существующая функция или таблица не удаляется и не меняется.
- Ошибки шагов, общих для всей задачи (`build_text_analysis_result`, версионирование и т.п.), после 3 попыток по-прежнему дают `needs_manual_review`. Без них задачу невозможно продолжить.

## Установка

1. Распаковать архив в «Загрузки». Из корня проекта:

   ```powershell
   powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\D10_job_continuity_v1\install_d10_job_continuity.ps1"
   ```

2. SQL Editor: миграция `supabase/migrations/20261011213000_d10_job_continuity_v1.sql`.
3. SQL Editor: `scripts/d10/59_d10_job_continuity_checks.sql`. В разделе `1_function` у всех трёх строк должно быть `"ok": true`.
4. Деплой, именно в этом порядке:

   ```powershell
   npx supabase functions deploy pipeline-supervisor
   npx supabase functions deploy job-orchestrator
   ```

   Сначала supervisor. Новый supervisor работает и со старым orchestrator. Новый orchestrator со старым supervisor бесконечно повторял бы ошибку семейства, а не считал её.
5. Перезапустить Expo.

Идущую задачу останавливать не нужно: она продолжится с новым supervisor, её состояние совместимо.

Откат: вернуть файлы из `*.d10-job-continuity.bak` и задеплоить обе функции. Новые SQL-функции можно оставить — без нового кода их никто не вызывает.

## Проверка

- После завершения текущей задачи запустить 59: раздел `2_last_jobs` покажет итог и списки.
- Раздел `3_continuity_state` показывает счётчики: были ли закрытые слова, пропущенные страницы, пропуск семейства.
