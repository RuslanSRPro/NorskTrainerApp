# D10: омонимы, части речи, семейство 360 и служебные слова — план изменений v2

Дата: 13.10.2026. Статус: **согласован**. v2: исправлен A3 (по данным 71), добавлены R11 и этап F (служебные слова, по данным 74).
Основание: живая задача `3779546f` («Er tiden. Jeg husker det.»), снимки 67–69, ревью Codex от 12–13.10.

## 0. Правила, которые фиксируем (ваши формулировки)

| # | Правило |
|---|---------|
| R1 | **Одиночное слово** (режим word_list): показываем все части речи и все омонимы. |
| R2 | **Слово или выражение в тексте**: часть речи определяется по смыслу, обрабатывается только она. |
| R3 | **Временное правило до грамматического графа.** Если в тексте часть речи определить нельзя, предлагаем все части речи, как для одиночного слова. В коде комментарий: `TEMPORARY until grammar graph: no context signal → all POS`. |
| R4 | Выбранная часть речи идёт вместе со словом до конца обогащения. Проверка и обогащение разных омонимов не смешиваются. |
| R5 | В карточках обучения показываем иконку омонимов. |
| R6 | **Серые кандидаты семейства 360** проверяются и обогащаются всегда. Есть контроль, что член семейства относится к правильному слову: лемма, лексема, часть речи. Статья фиксируется в базе, но в приложении не показывается. |
| R7 | **Границы неоднозначности.** Одна форма в тексте не может одновременно попасть в две карточки. |
| R8 | **Одинаковые формы, несколько статей-родителей** → одна карточка, одна часть речи, одна запись, переводы — варианты. Механизм переводов не трогаем: сортировка и до 3 переводов из мастер-вариантов. Только проверяем. |
| R9 | **Разные формы, одна часть речи** (være II «быть» er/var/vært и være III «чуять» værer/væra) → две карточки с одной леммой. У каждой свои переводы, только из её статьи, и в приложении показываются только её мастер-варианты. |
| R11 | **Служебные слова** хранятся в базе как лексемы с пометкой «служебное» и со своими формами. Они участвуют в разборе текста, но не в обучении. Отклонённое служебное слово не делает задачу «needs manual review». |
| R10 | **Выражение с несколькими родителями** (bite i det sure eplet → bite, eple) — **не омоним**. Это одна карточка выражения с несколькими связями Lexeme360. |

## 1. Что показала задача 3779546f

- Обогащение прошло полностью: 68 элементов, журнал без ошибок. Задача шла 3 ч 20 мин.
- **«husker» (глагол) не обработан.**
  - Ordbøkene вернул две статьи глагола, 24686 и 24687. Обе привязаны к одной лексеме `d400112d`. Правило «ровно одна привязанная статья» не сработало → `pos_unverified` → глагол не продвинут и не обогащён. Нарушены R2 и R8.
  - Продвинут клон-существительное «huske» («качели»), потому что `expand_multi_pos_occurrences_for_job` (с 12.08) не различает текст и одиночное слово. Нарушен R2.
- **Окно «Needs manual review»** появилось дважды:
  - во время обогащения: `get-job-status` принял `done` оркестратора за конец задачи;
  - в конце: supervisor посчитал заблокированными **Jeg, det** (служебные слова, отклонённые правилом) и **глагол huske**. Серые карточки семейства (3) supervisor уже учитывает отдельно, причиной они не были. В v1 здесь была ошибка.

## 2. Этапы

Каждый этап — отдельный пакет: тесты, установщик со сверкой хэшей, откат. Этапы A–C не меняют структуру базы. Этап D меняет и требует отдельного согласования после инвентаризации.

### Этап B. Часть речи в тексте (R2, R3, R4)

| # | Изменение |
|---|-----------|
| B1 | `expand_multi_pos_occurrences_for_job`: в режиме текста (`isolated_mode = false`) клоны других частей речи создаются **только** без сигнала из контекста: `disambiguation_rule = no_signal_fallback_*` или `v2_resolution_status = ambiguous_unresolved` без правила. Если разбор выбрал часть речи по контексту (например, `preceded_by_subject_pronoun`), клонов нет. Режим word_list не меняется (R1). Комментарий TEMPORARY (R3). |
| B2 | Аудит «часть речи не теряется» — SQL-проверка по задаче. У каждого элемента часть речи совпадает: в элементе, в продвинутой лексеме, в доказательстве Ordbøkene, в записях журнала обогащения. Любое расхождение — строка отчёта. Подозрение для проверки: в `candidate_provenance` клона «Er» (сущ.) лежит доказательство глагола (статья 69211). Это может быть только копия доказательства родителя, а может быть и смешение. Проверяем, а не предполагаем. |
| B3 | Цепочки обогащения работают по `lexeme_id`/`expression_id` элемента, а не по тексту леммы. Проверяем каждую из 11 цепочек: где поиск идёт по `lemma` без `pos` или статьи, это ошибка R4. |

Проверка: тексты «Jeg husker det.» (только глагол), «Er tiden.» (сигнала нет → все части речи, по R3), одиночное «huske» (все омонимы, R1).

### Этап F. Служебные слова (R11, данные запроса 74)

Сейчас: 36 правил, все без части речи. У 12 нет лексемы (da, deg, ei, eller, fra, hos, i, jo, men, også, oss, så). 21 лексема помечена `excluded`, но du и dere не помечены, а у «på» часть речи noun. Ни у одной служебной лексемы нет форм. Обучение уже фильтрует `is_learning_lexeme = true`.

| # | Изменение |
|---|-----------|
| F1 | Правила получают часть речи. Сейчас правило по лемме задевает полноценные омонимы: «ved» (сущ. «дрова») исключено из обучения; тот же риск у for, en, men, så. Перед изменением — список всех затронутых лексем на согласование. |
| F2 | Создать недостающие лексемы и связать формы с основной лексемой (jeg → meg, min, mitt, mine; han → ham, hans; de → dem, deres). Формы и часть речи берутся из Ordbøkene. Отдельные лексемы-формы (meg, seg) — показать, прежде чем менять. |
| F3 | Пометить du и dere. Лексему «på» (noun) показать до любых изменений. |
| F4 | Разбор текста привязывает служебное слово к его лексеме. В карте слов оно распознано и окрашено как служебное; в обучение не попадает. |
| F5 | Обогащение служебных слов: переводы и формы — да; семейство 360 и примеры — по решению. Строки прогресса (10 шт.) не удаляются: обучение их и так не показывает. |

### Этап D. Модель «разные формы → разные карточки» (R8, R9)

Сначала только **инвентаризация** (только чтение), потом решение.

D0. Инвентаризация 44 лексем с несколькими статьями. Для каждой:
- сравнение парадигм по статьям Ordbøkene: одинаковые → случай R8, разные → R9;
- откуда переводы (`source_entry_id` Lexin), есть ли доказанная связь «запись Lexin → статья»;
- прогресс обучения по лексеме.

Важно (Codex): `sense_rank` Lexin — это не номер статьи Ordbøkene. Переводы раскладываются по статьям только при доказанной связи. Если связь не доказана, перевод остаётся на основной карточке с пометкой, а не угадывается. Пример смешения: у være (глагол) сейчас переводы двух записей Lexin, 5707 и 5708.

D1 (после D0 и вашего решения). Схема:
- в `lexemes` добавляется ключ омографа (`homograph_key`, по умолчанию пустой у всех существующих);
- уникальный индекс `(lemma, pos)` заменяется на `(lemma, pos, homograph_key)`;
- новая таблица привязки «карточка → статья» (`lexeme_id`, `dictionary_code`, `article_id`, доказательство);
- у R8 несколько статей на одну карточку, у R9 — своя карточка на каждую парадигму.

D2. Разделение только лексем случая R9:
- прогресс обучения остаётся на карточке основного значения;
- новая карточка начинает с нуля;
- переводы и примеры переходят только с доказанной связью.

D3. Переводы:
- R8 — текущий механизм без изменений (проверка: до 3 мастер-вариантов, сортировка);
- R9 — каждая карточка показывает только свои мастер-варианты.

### Этап E. Иконка омонимов в обучении (R5)

- RPC: для лексемы — «соседи» с той же леммой: другие части речи (R1) и другие карточки той же части речи (R9). Отдельно отдаётся число значений внутри карточки (R8).
- Интерфейс: иконка в `TrainingModeRenderer`, `TrainingFlashcard`, `Lexeme360`. По нажатию — список с переходом в соседнюю карточку. Номера статей не показываются.
- Порядок частей речи в списке — по частотности Kelly. Выбор статьи по частотности не делается: Kelly не различает омонимы.

## 3. Порядок и зависимости

```
A (ошибки) → B (часть речи) → C (семейство) → F (служебные слова) → D0 (инвентаризация) → решение → D1–D3 → E
```
A–C не зависят от решения по D. E можно сделать после A для случаев R1/R8, а для R9 — после D.
