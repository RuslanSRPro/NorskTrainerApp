## Что делает пакет

| # | Что | Где |

| 2 | **Продвижение выбирает карточку по статье** из доказательства Ordbøkene, затем основную. Раньше бралась случайная | `promote_verification_results_for_job` |

| 5 | **Lexin по части речи и формам** (D3): если у слова есть вторая карточка, запись Lexin идёт к той карточке, чьи формы совпадают со склонением записи (E-mor). Нет склонения → перевод не берётся, его делает AI по определению своей статьи | lexin-enrichment-worker + `_shared/d10-lexin-homograph-forms.ts` |
| 6 | **Приложение:** выбор части речи «bok — noun · книга»; 🟣 отдельный список «Омонимы и другие значения» под разметкой слов; легенда; в тексте при равенстве показывается основная карточка | `reading.tsx`, `services/api.ts` |
| 7 | **Включение вторых карточек:** снимается старый индекс (лемма, часть речи). **Последний шаг** | миграция `20261015090900` |

Подробнее по шагу 4:
- **Формы разные** → вторая карточка: та же лемма и часть речи, ключ — римский номер омографа (II, III), привязка к своей статье. Карточка добавляется в задачу отдельным элементом и проходит обычный путь: проверки, продвижение по статье, все цепочки обогащения.
- **Формы одинаковые** → одна карточка (R8).
- **Статья без заголовка** («på tide») → пропуск.
- **У основной карточки нет статьи** → основной становится статья с меньшим римским номером.
- **Уже созданная вторая карточка** снова добавляется в каждую новую задачу с этим словом.
- **Сбой шага** задачу не роняет, только пишется в журнал.

Повторный запуск любой миграции ничего не меняет. Если живое определение функции не такое, как ожидалось, миграция останавливается, ничего не меняя.

## Проверено

- **Локально, PostgreSQL 16, на живых определениях функций.** В тесте две карточки «bok», у основной специально больший внутренний id.

| Проверка | До | После |
|---|---|---|
| кандидаты «bok» | первой bok II | первой основная |
| поиск по лемме «bok» | bok II | основная |
| продвижение «bøker» (статья 6790) | **bok II** ❌ | основная ✅ |
| продвижение «bok» без статьи | **bok II** ❌ | основная ✅ |
| продвижение «boker» (106786) | bok II | bok II |

- **Вторая карточка:**
  - до включения — отказ «не включено»;
  - после включения — bok II с ключом II и статьёй 106786; повтор возвращает её же;
  - добавление в задачу — 1 элемент и 5 проверок, без дублей;
  - кандидаты после решения — пусто;
  - уже существующая карточка добавляется в новую задачу.
- **Модули (тесты Node на настоящих статьях Ordbøkene 106786, 69212 и на ответе Lexin для «bok»):** 9 + 6 PASS.
  - Запись Lexin 506 «книга» (`ei (en) bok boka (boken) bøker bøkene`) идёт к bok I и **не** идёт к bok II.
  - Запись Lexin «бук» — это лемма «bøk» с формами bøker, к «bok» она не относится. У bok II перевод будет от AI.
- **Синтаксис** всех изменённых TS/TSX проверен.

## Что нужно знать

- Пока не применена последняя миграция, поведение не меняется: шаг 4 молча пропускается.
- Если элемент второй карточки не пройдёт проверку Ordbøkene (не должно — он проверяется по своей статье), он остановится на допуске, и задача покажет его как заблокированный. Это видно в итоге задачи.
- Цепочка authoritative (попутный пункт B3) в этот пакет не вошла: её вызов Ordbøkene работает без записи.
