# Grammar Graph — рабочий порядок (замена старой «единой инструкции»)

Цель: активировать правила загруженной грамматики NRG в Grammar Graph и подключить граф к «Разбору своего текста». Работа ведётся пакетами; источник правды — эта папка.

## Начало нового чата
1. Прочитать только `grammar-evidence/HANDOFF.md` и записи `registry.json`, на которые он ссылается.
2. Не изучать заново проект и базу: всё доказанное — в матрице (PROVEN). Повторно проверять только то, что `matrix.csv` показывает как STALE и что нужно текущему пакету.
3. C0: `git rev-parse HEAD`, ветка, `git status --short` для затрагиваемых путей. Если HEAD отличается от HANDOFF — сначала свериться.

## Пакет = группа правил, три запуска
1. Разведка: один read-only SQL, отвечает на все вопросы пакета одним компактным JSON (≤ ~5 КБ). Без полных определений функций.
2. Применение: один SQL-скрипт `DRAFT_..._REVIEW_ONLY.sql` с gate внутри транзакции (golden + проверки ACL) и полным откатом при сбое. Применяет владелец после одобрения.
3. Запись: `python3 grammar-evidence/tools/record-proof.py ...` (артефакт, registry, history, индекс одной командой), затем коммит по команде владельца.

## Обмен файлами (режим по умолчанию)
- ИИ не читает проект и базу через связь с ПК без нужды: это медленно и дорого.
- Нужны данные (код функций, строки таблиц, git) → ИИ даёт один скрипт-выгрузку (SQL или PowerShell), который кладёт всё нужное одним компактным файлом в Downloads; владелец прикладывает файл в чат.
- Нужно применить код, записать в матрицу или обновить HANDOFF → ИИ даёт файл(ы) и одну команду PowerShell, владелец запускает и присылает вывод.

## Правила
- Активируем шаблоны операторов, а не правила по одному: один шаблон → массовая генерация manifest для всех правил этого типа → golden → shadow.
- Порядок: сначала самые частые правила (встречаются в каждом предложении).
- READY ≠ ACTIVATED. Правила по умолчанию с исключениями дают preferred/soft или ambiguous, никогда chosen; окончательный выбор за парсером; граф не вставляет и не удаляет кандидатов (контракт `contracts/analyze-text-graph-integration-v3.md`).
- ИИ не выполняет ничего в Production: только готовые файлы (SQL / PowerShell) в Downloads; владелец запускает и прикладывает короткий результат.
- Скрипты возвращают сводку (проверено / прошло / упало + список упавших); подробности — в файл-артефакт.
- Ключи не в чате: PowerShell берёт service-ключ из `.local-secrets/supabase-secret-v2.dpapi` (DPAPI) и не печатает его.
- Ничего работающего не удалять; без попутных правок; коммит только по команде.
- Когда чат стал длинным — обновить HANDOFF.md, закоммитить и открыть новый чат.
- Архитектурные решения — Opus; рутинные пакеты по готовому шаблону — Sonnet.
