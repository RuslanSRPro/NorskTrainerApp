## B1. Часть речи в тексте (R1–R3) — миграция `20261013200000`

`expand_multi_pos_occurrences_for_job` больше не создаёт клоны других частей речи, если **в тексте** разбор уже выбрал часть речи по контексту (`preceded_by_subject_pronoun` и т. п.). Без изменений:
- одиночное слово (word_list) — все части речи (R1);
- текст без сигнала контекста (`no_signal_fallback_*`, `no_context_all_candidates_returned`) — все части речи. Это **временно, до грамматического графа**, и в коде так и написано (R3);
- старые задачи без флага `isolated_mode`.

Остальная часть функции совпадает с живым определением. Перед заменой миграция проверяет, что живая версия ожидаемая; если нет — останавливается и ничего не меняет.

Локальный тест: до — во всех 6 случаях 1 клон; после — текст с правилом контекста 0, остальные 5 случаев 1 (без изменений).

## C. Семейство 360

**C-1. Семейство для набора статей** — миграция `20261013200100`. Продолжение A1: для лексемы, подтверждённой набором статей (huske 24686 + 24687), корнем семейства становится каждая статья набора. В журнале остаётся точная `root_article_id`. Одна статья работает как раньше; несколько статей **без** привязки к лексеме по-прежнему не используются.
Локальный тест: набор → 3 выражения из обеих статей; одна статья → 2, как и раньше; непривязанные статьи → 0; повторный вызов ничего не добавляет.

**C-2. Серые выражения проходят и AI-обогащение** (ваше решение 13.10) — `job-enrichment-batch-worker`. Раньше AI-перевод получали только допущенные выражения. Страница выражений, как и раньше, содержит только допущенные выражения и серые члены семейства этой задачи. AI-обработчику для выражений статья не нужна, так что цепочка не рвётся.

**C-3. Доказательство собственной статьи выражения (вариант «б»)** — миграция `20261013200200`.
- Если проверка Ordbøkene выражения подтвердила **его собственную точную подстатью**, пишется одна строка `expression_source_evidence` (`ordbokene` / `own_article`, номер статьи, родитель, задача).
- Статус выражения `expression_review_status` становится `verified`. **Важно:** одна только строка не помогла бы — проверка полноты требует и строку, и статус `verified`. А правило статуса понимало только `expr_entry` и `uttrykk`. Поэтому функция статуса теперь сохраняет `verified` для подстатьи с таким доказательством. Других случаев это не касается, сама проверка полноты не меняется.
- Срабатывает триггером на запись проверки. Ошибка триггера никогда не ломает запись `lexical-worker`: она пишется в журнал, а запись проходит.
- Заполнение по уже выполненным проверкам (backfill) входит в миграцию и выводит число записей.

Серое выражение (собственная статья не совпала) ничего не получает.
Локальный тест: совпавшее → 1 строка и `verified`, повторное обновление не создаёт дубля; серое → 0 строк, `partial`; после обновления `naob_status` статус `verified` сохраняется; повреждённое доказательство не ломает запись.

**C1 (контроль принадлежности)** — по данным 76 для задачи 18efc887: у всех членов семейства корень продвинут в этой задаче, а его статья есть в доказательстве. Расхождений нет, менять нечего.

## F. Служебные слова

**F3** — миграция `20261013200300`: du и dere помечены как служебные (`excluded`, не для обучения). У них нет строк прогресса.

**F4** — приложение (`services/api.ts`, `reading.tsx`). Раньше служебные слова исключались из словаря чтения, поэтому в карте слов «Jeg» был **красным**, а среди кандидатов на добавление стоял «нет в базе». Теперь:
- приложение загружает список служебных слов: лексемы с пометкой и значения правил;
- в карте слов они **серые** («⚪ Служебное слово (не для вивчення)»), нажатие ничего не открывает;
- в кандидаты на добавление они не попадают и считаются в покрытие текста;
- обычные слова (жёлтые/зелёные) имеют приоритет: «så» как форма глагола «se» остаётся словом из базы.

Деплоя нет, приложение просто перезагружается.

**Сознательно НЕ сделано (требует отдельного шага):**
- **F1 — существительное «ved» («дрова») пока остаётся исключённым.** Это единственная лексема «ved» в базе, поэтому разбор текста превращает в неё частый предлог «ved». Если сейчас вернуть её в обучение, каждый предлог станет «дровами». Сначала нужен F2: лексема-предлог «ved».
- **F2 — лексемы служебных слов с формами** (jeg/meg/min…). Модуль форм умеет только verb/noun/adjective/determiner. Для местоимений его нужно расширить — это отдельный пакет.
- Лексема «på» с частью речи noun не трогается.
