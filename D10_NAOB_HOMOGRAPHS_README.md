# D10: деление существительного по статьям NAOB (одно правило с Ordbøkene)

Согласовано 24.10.2026. Ставится после D10_naob_forms_v1, D10_translation_cards_v1 и D10_r9_evidence_v1.

## Правило

**Чьи статьи сравниваем:**

| У слова этой части речи | Источник |
|---|---|
| есть статьи Ordbøkene | только Ordbøkene, как раньше |
| статей Ordbøkene нет, есть статьи NAOB | **NAOB** (новое; пока только существительные) |
| статей нет нигде | одна серая карточка / привязка к существующей (вариант А) |

**Решение — одна и та же функция для обоих источников** (`decideHomographs`):

| Формы | Значение | Результат |
|---|---|---|
| одинаковые | разные | одна карточка (R8) |
| разные, в том числе другой род | своё у каждой статьи | своя карточка II, III (R9) |
| разные | то же, что у основной | одна карточка, «на проверку» |
| нет своих форм или своего толкования | — | карточки нет, «на проверку» |

- **Основная карточка** получает статью с наименьшим номером. Для brenne это brenne_2, «avsvidd skoggrunn».
- **Формы NAOB** сравниваются вместе с артиклем: *en* brennen и *et* brennet — разные парадигмы. NAOB перечисляет не все формы, поэтому список, который входит в другой при том же артикле, считается тем же.

Для brenne (сущ.) ожидается:

| Статья | Толкование | Карточка |
|---|---|---|
| brenne_2 | avsvidd skoggrunn | основная |
| brenne_3 | ved til brensel | brenne II |
| brenne_4 | brennende følelse | своя карточка III, если формы отличаются; иначе R8 (одна карточка с brenne_2) |

## Где это происходит

1. **`job-orchestrator`**: после шага омографов Ordbøkene вызывается `naob-forms-worker` в режиме `split` для существительных задачи без статьи Ordbøkene.
   - Новые карточки **сразу добавляются в задачу**, поэтому проходят проверки, переводы и всё обогащение. Обычная цепочка форм идёт последней и для этого не годится.
   - За один вызов обрабатываются 2 слова, остальные — на следующем шаге.
   - Слово отмечается как обработанное в этой задаче, и повторно в ней не делится.
   - Сбой никогда не останавливает задачу.
2. **Карточка ↔ статья** хранится в `private.d10_naob_homograph_cards_v1`. Повторная обработка ничего не дублирует.
3. **Цепочка форм:** карточка, привязанная к статье NAOB, берёт формы только этой статьи и пометку «на проверку» не получает.
4. **AI-перевод:** у карточки со своей статьёй NAOB контекст — **только её толкование**. «Дрова» не смешиваются с «выжженной землёй».
   - Раньше AI отказывался переводить вторую карточку без статьи Ordbøkene (`NO_ARTICLE_NOT_FOR_SECOND_CARD`). Для карточек с привязкой к статье NAOB этот отказ снят: статья сама различает карточки.
   - Переводится только перевод, без примера и заметок, как у любого слова без статьи.
5. **Серая привязка:** элемент второй карточки, добавленный в задачу, привязывается к **своей** карточке (по номеру II/III), а не к основной.

## Что не меняется

- Слова со статьёй Ordbøkene этой части речи — правила Ordbøkene, тот же код.
- Слова с одной статьёй NAOB — она становится статьёй основной карточки, и формы публикуются как раньше.
- Допуск и звёзды.
  - Новая карточка копирует свидетельства основной (NAOB, существительное), поэтому у неё те же звёзды.
- Скрытые карточки (bære II) в задачу не добавляются.

## Иконка омонимов и связанное

- **Иконка** покажет все карточки с леммой: у brenne это глагол I и II, существительные I, II и, возможно, III. Строки различаются переводом, номера статей не показываются (как договаривались).
- **Распознавание в тексте:** у каждой карточки свои формы NAOB. «brennen» → I, «brennet» → II. Голое «brenne» без артикля по форме не различить — это задача грамматического графа (артикль *en/et*, согласование прилагательного).
- **Lexin:** у карточек NAOB нет форм Ordbøkene, поэтому статьи Lexin по правилу R9 к ним не привязываются, перевод делает AI. Пометка Lexin «на проверку» у них ожидаема.
- **Тренировка:** новые карточки — обычные учебные, но в тренировку попадают, только если ты их добавишь.

## Проверено

- **10 новых тестов:**
  - толкование brenne_2 (без цитат);
  - *en*/*et* — разные парадигмы;
  - brenne_2 + brenne_3 → основная + II;
  - те же формы → R8;
  - только род → проверка;
  - без толкования → проверка;
  - worker: деление, публикация форм обеим карточкам, добавление в задачу;
  - слово с формами Ordbøkene не трогается;
  - 2 слова за вызов + `has_more`;
  - карточка с привязкой берёт только свою статью.
- **Прежние тесты:** формы NAOB 15, R9 15, AI 27, Lexin R9 5 — все проходят.
- **PostgreSQL 16:**
  - основная + II + III, повтор без дублей;
  - отказы: вторая основная, плохой slug, не основная карточка;
  - кандидаты задачи и отметка «обработано»;
  - элемент II привязывается к карточке II, обычный — к основной;
  - миграция повторяется без изменений;
  - 163 выполняется.
